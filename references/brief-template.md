# 任务书模板

每个维度一份，存成 `<目的地>-<维度>-brief.md`，再派给 agent。复制下面的内容并填空。

```markdown
# 任务书：<目的地> <维度名>

你是<领域>专家。对 <目的地> 的 <维度> 做一份调研。

读者：<旅行者情况：人数、性别、会的语言、经验>。目的是<教会她/帮他做决定/建立价格基准>。

## 必须覆盖
1. ...
2. ...

## 资料质量要求（硬性）
- 事实、推算、判断分开标注；查不到就写“未找到公开数据”，不粉饰。
- 文内用 [n] 标注引用，文末列来源 URL 清单。
- 价格写区间，并标性质：实测 / 官方列价 / 按层级推算。
- 店名和地点联网核实真实存在；核实不了的明写“未核实”。
- 不编造 URL；图片找不到就写“无图”。
- 当地语言和法语专有名词保留原文，后面括号写中文。
- 写实用的，不要旅游手册腔，不要空洞抒情。
- <若是城市理解类>：要有社会学深度，写“这对旅行者意味着什么”。

## 图片（需要时）
- 优先 Wikimedia Commons。每张记下作者、许可证、文件名。
- 区分实拍和示意图。
- 抓图注意限流，出现 429 就停下，不要批量连续请求。
- 尽量取 1000px 以上，不要只拿 500px 缩略图。

## 输出
写到 <路径>.md。完成后用一句话说明写完了，不要把全文再输出一遍。
```

## 评审任务书（交叉评审用）

```markdown
你是资深评审专家。读 <作者 agent> 写的 <路径>.md，逐条批判：
事实错误、遗漏、编造来源、不实用内容、安全风险（<这个主题里最危险的点>）。
批判要具体到条目，给出修正建议。写到 <路径>-critique.md。
```

## 整合任务书

```markdown
读三份文件：你的报告（作为骨架）、另一位的报告（取你没有的优点）、对你报告的批判（里面指出的问题你的报告也有同类缺口，必须一并补齐）。
输出最终整合版到 <路径>-final.md。
```
